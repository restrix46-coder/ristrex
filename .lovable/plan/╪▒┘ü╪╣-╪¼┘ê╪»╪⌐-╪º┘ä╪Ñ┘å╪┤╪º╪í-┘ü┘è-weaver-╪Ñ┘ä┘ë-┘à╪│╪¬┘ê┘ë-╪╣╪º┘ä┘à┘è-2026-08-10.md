# رفع جودة الإنشاء في Weaver إلى مستوى عالمي

## خلاصة الدراسة

فحصت محرّك البناء الحالي: `src/routes/api/chat.ts` (3442 سطر)، `src/lib/agent/system-prompt.ts`، `src/lib/design-blueprints.ts`، `src/lib/art-direction.ts`، `src/lib/brand-kit.ts`، `src/lib/design-critic.server.ts`، `src/lib/verify.server.ts`.

**الوضع الحالي قوي في الحوكمة، ضعيف في المادة الأولية.** كل معايير الجودة مكتوبة كـ *نصّ إرشادي* داخل موجّه النظام (أكثر من 190 سطراً من القواعد النثرية). النموذج يقرأها ثم يكتب HTML/CSS من الصفر في كل مشروع. هذا هو سبب التفاوت: الجودة تعتمد على مزاج النموذج في تلك الجولة.

**ما تفعله المنصات العالمية مختلف جذرياً:**

| المنصة | مصدر الجودة الحقيقي |
|---|---|
| Lovable / v0 | لا يكتب النموذج CSS أساساً — يركّب مكوّنات جاهزة (shadcn/Tailwind) فوق نظام tokens مُصرّف مسبقاً |
| Bolt / Replit | قوالب starter حقيقية تعمل قبل أول توكن من النموذج |
| Figma Make / v0 | توليد **عدّة اتجاهات** ثم اختيار، بدل محاولة واحدة |
| Manus | حلقة تحقّق بمقاييس رقمية، لا حكم لغوي |

الفجوة الجوهرية: **Weaver يصف الجودة، والمنافسون يشحنونها كشيفرة.**

---

## المحاور الستّة للخطة

### 1. مكتبة مكوّنات مُصرّفة (أهم بند)
بدل وصف `.btn` و`.card` في الموجّه، نشحن **Weaver UI**: ملفات CSS/HTML حقيقية جاهزة تُنسخ إلى مساحة المشروع قبل كتابة أي ملف.

- `tokens.css` مولّد من `brand_kit` (موجود جزئياً) + `ui.css` يحتوي 20–25 مكوّناً مُتقن الصنع: أزرار، بطاقات، navbar بقائمة جوال تعمل، hero، bento grid، جدول أسعار، FAQ accordion، شهادات، فوتر، حالات فارغة، skeletons.
- كل مكوّن يأتي بـ **قصاصة HTML مرجعية** يقرأها الوكيل بأداة `ui_snippet` ويلصقها ويعدّل محتواها فقط.
- النتيجة: النموذج يكتب **محتوى وتركيب**، لا CSS خام. هذا وحده يرفع الأرضية الدنيا للجودة بشكل حاسم.

### 2. قوالب انطلاق حقيقية (Starter Kits)
6–8 قوالب كاملة تعمل من اللحظة صفر لكل نوع منتج (SaaS، متجر، فاخر، تحريري، خدمي، بورتفوليو، لوحة تحكّم، هبوط). القالب ليس وصفاً — بل ملفات فعلية مُختبرة مسبقاً (تمرّ بوابة الجودة قبل شحنها). الوكيل يختار القالب، يحقن الهوية، ثم يخصّص.

### 3. توليد ثلاثة اتجاهات واختيار (Design Directions)
قبل البناء الكامل: توليد 3 نسخ من الصفحة الأولى فقط بثلاث توليفات مختلفة (تركيب/كثافة/إيقاع) مع نفس الهوية، التقاط لقطاتها، وعرضها في المحادثة عبر بطاقة اختيار. المستخدم يختار → يُبنى الموقع كاملاً على الاتجاه المختار.

### 4. ناقد بصري بمقاييس رقمية (لا حكم لغوي فقط)
`design-critic.server.ts` حالياً يعيد نصّاً وSCORE ذاتياً. نضيف **قياساً حتمياً** من DOM الحقيقي داخل Playwright:

- التزام مقياس المسافات (نسبة القيم خارج 4/8px)
- عدد أحجام الخطوط الفريدة (> 7 = رسوب) وعدد الألوان الفريدة (> 12 = رسوب)
- تباين WCAG محسوب فعلياً لكل نص
- توازن الفراغ الأبيض، عرض المحتوى الأقصى، الإيقاع الرأسي بين الأقسام
- حالات focus-visible لكل عنصر تفاعلي، القائمة على الجوال، التمرير الأفقي

النتيجة رقم مركّب `designScore` مخزّن في قاعدة البيانات لكل مشروع، والنشر يُمنع تحت 85. الناقد المرئي يبقى لكن كطبقة ثانية فوق الأرقام.

### 5. جودة المحتوى والنسخ (Copy Quality Gate)
مرحلة كتابة منفصلة قبل البناء: توليد نصّ الموقع كاملاً (عناوين، وعود، أوصاف خدمات، أسئلة شائعة، CTA) بنموذج مخصّص للكتابة العربية المقنعة، وحفظه كملف `content.json`. الوكيل يبني فوق المحتوى بدل اختراعه أثناء الكتابة. يمنع النصّ العام والادّعائي.

### 6. تنظيف المحرّك وتقليص الموجّه
- تقسيم `src/routes/api/chat.ts` (3442 سطر) إلى وحدات أدوات مستقلة تحت `src/lib/agent/tools/`.
- تقليص موجّه النظام من ~190 سطراً إلى ~70: كل قاعدة يمكن فرضها بالكود تُنقل إلى الكود (الفاحص، المكتبة، البوابة). القواعد المفروضة برمجياً لا تُكرَّر في الموجّه — هذا يحرّر سياقاً للنموذج ويرفع دقّته.

## التفاصيل التقنية

**ملفات جديدة**
- `src/lib/design/ui-library.ts` — تعريف المكوّنات + قصاصات HTML
- `src/lib/design/ui.css.ts` — مولّد CSS المكوّنات المرتبط بالـ tokens
- `src/lib/design/starters/*.ts` — القوالب الثمانية
- `src/lib/design/metrics.server.ts` — القياس الحتمي داخل Playwright
- `src/lib/content/copywriter.server.ts` — مرحلة المحتوى
- `src/lib/agent/tools/` — تفكيك أدوات `chat.ts`
- `src/components/agent/direction-picker.tsx` — بطاقة اختيار الاتجاه

**ملفات تُعدَّل**
- `src/lib/agent/system-prompt.ts` — تقليص وإعادة صياغة
- `src/lib/design-critic.server.ts` — دمج المقاييس الرقمية مع المراجعة المرئية
- `src/lib/verify.server.ts` — إضافة فحوص المكتبة والالتزام بالـ tokens
- `src/lib/brand-kit.ts` — إخراج `ui.css` بجانب `tokens.css`
- `src/lib/publish.functions.ts` / بوابة النشر — عتبة `designScore`
- قاعدة البيانات: عمود/جدول لتخزين نتائج الجودة لكل مشروع

**مبدأ حاكم**: أي قاعدة جودة يمكن فرضها برمجياً لا تُترك للموجّه. الموجّه للقرارات، الكود للمعايير.
